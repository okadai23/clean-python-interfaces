Use `/clean-tdd-prototype`, `/karpathy-guidelines`, and `/doc-maintenance`.

Workflow:

1. Restate acceptance criteria.
2. Identify architecture boundaries.
3. Add or update failing tests first where feasible.
4. Implement the simplest sufficient change.
5. Keep the diff surgical.
6. Update impacted docs or give a no-doc-change rationale.
7. Run verification.
8. Report changed files, tests, commands, assumptions, and residual risk.
